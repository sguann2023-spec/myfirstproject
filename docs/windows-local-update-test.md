# Windows 本地启动更新测试

只需两个安装包和一个固定目录，不需要 Node.js、环境变量或手动启动服务。
更新测试入口只在 `AppUpdater.ts` 的更新源选择处生效，不改变下载及安装时机。

## 准备

1. 重新打包 1.7.19，包含当前的磁盘测试入口及“本次后台下载、后续启动安装”逻辑。
2. 打包 1.7.20，包含 NSIS 进度页面修改。两个包保持相同应用标识和签名配置。
3. 打包使用 `--publish never`，不运行上传或发布脚本。
4. 将 1.7.20 构建产物复制到 Windows 的固定目录：

```text
C:\VectCut-update-test\
  latest.yml
  VectCut-Setup-1.7.20-x64.exe
  VectCut-Setup-1.7.20-x64.exe.blockmap
```

必须使用 1.7.20 构建生成的 `latest.yml`，其中包含版本、文件名和 SHA-512。
不要放入旧版的清单，不要在复制后重命名 EXE。

## 验证两次启动

1. 安装 1.7.19，确保自动更新开启，正常从桌面图标启动。
2. 本次启动正常进入登录，后台从测试目录下载，不等待下载完成。
3. 等应用日志出现 `update downloaded`，确认仍运行 1.7.19，没有自动安装。
4. 正常退出，确认退出没有启动安装器。
5. 再从桌面图标启动。此时才安装已准备的更新，显示独立进度窗口。
6. 确认无需选择安装范围、目录或点击完成，新版自动启动且版本为 1.7.20。
7. 确认安装目录不变，桌面快捷方式仍可正常启动。

日志出现 `Using local Windows update test source` 表示使用了本地目录。
内部本机 HTTP 适配由应用自动管理，不需要用户操作。
本地源缺文件或出错不会回退到线上；SHA-512 和签名校验保持启用。
本地测试禁用差分下载。

## 清理

测试完成后移走或重命名 `C:\VectCut-update-test`，下次检查恢复普通更新源。
目录不存在时业务逻辑不变；macOS 不使用此入口。
若新版没有包含磁盘测试入口，启动后会恢复普通更新源。
建议两个包都使用当前代码构建，避免自动重启后访问线上更新源。
正式发布前可移除测试入口，避免正式客户端保留固定目录覆盖能力。

安装中断不保证完整回滚，破坏性测试请使用有快照的虚拟机。
