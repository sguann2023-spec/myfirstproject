# 每日领取积分接口约定

当前前端使用 `POST /lago/daily/checkin` 领取积分，使用
`GET /lago/balance` 的 `total_balance` 更新总余额。

沿用 `https://open.vectcut.com`、Bearer Token 鉴权和现有余额接口的
snake_case 字段风格；响应直接返回 JSON 对象，不增加 `data` 包装层。

## 当前前端调用

开发和生产环境均调用正式接口，不再使用 mock 数据。
已领取状态按账号缓存到本地，北京时间当天有效。查询结果为已领取或领取成功后写入缓存；
当天后续刷新、重新挂载、窗口聚焦及跨窗口通知均优先读取缓存，不再请求查询接口。
未领取状态和查询失败结果按账号、北京时间日期及本次客户端启动标识缓存，启动时首次查询一次；
后续挂载、打开设置页或刷新窗口复用结果。重启客户端后允许重新查询，已领取的当天缓存仍优先使用。
北京时间日期变化后，下次读取不再使用前一天的缓存。领取请求失败时允许绕过本次启动缓存，确认是否已到账。
只有用户主动点击才调用领取 POST。请求中同步加锁，阻止快速连点重复领取。
领取后首页保留浮窗，显示禁用的“今日已领取”按钮，用户可手动关闭；设置页同样禁用领取按钮。
同窗口使用事件同步，跨窗口使用 BroadcastChannel 通知读取状态缓存，并刷新首页余额。
目前没有定时轮询或跨天自动刷新；重新聚焦窗口仅刷新余额，不查询签到状态。

## 查询今日领取信息

新增 `GET /lago/daily/checkin/reward-status`，无请求体。此接口只查询，不能发放积分。

```json
{
  "period": 123,
  "reward_credits": 80,
  "claimed_today": false
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| period | integer | 正整数活动期数，由后端定义和更新，不由前端根据日期推算 |
| reward_credits | number | 当日可领积分数，非负；已领取后仍返回本日奖励额度 |
| claimed_today | boolean | 当前登录用户当天是否已领取，后端为唯一判断依据 |

成功响应只包含以上三个字段，均为必填。当天以服务端 Asia/Shanghai 时区为准。
积分数和期数仅为示例，前端不写死。

## 点击领取

保留 `POST /lago/daily/checkin`，无请求体；建议后端统一为以下成功响应：

```json
{
  "period": 123,
  "reward_credits": 80,
  "claimed_today": true
}
```

成功响应仅包含与查询接口相同的三个字段。当天重复请求也返回 HTTP 200、
`claimed_today: true`，不重复发放积分；后端需按用户和业务日期原子去重，
覆盖跨设备和并发请求。`reward_credits` 始终表示当日奖励额度，已领取后仍保持该额度。

领奖成功后前端调用现有 `GET /lago/balance` 获取 `total_balance`，
不在本地累加余额。余额刷新失败不应撤销已领取状态，也不应提示领取失败。

失败使用非 2xx HTTP 状态和统一错误对象，例如：

```json
{
  "code": "CHECKIN_UNAVAILABLE",
  "message": "当前活动暂不可领取，请稍后重试"
}
```

未登录使用 401；临时服务失败使用 503。不要将业务失败返回为 HTTP 200。
请求超时或网络中断时结果可能未知，前端应重新查询状态后再允许领取。

## 弹窗交互

- 首页初始化仅查询状态、刷新余额，禁止调用领取 POST。
- 左下角无蒙层浮窗，230 × 99 CSS px；标题为 `VectCut加油站第${period}期`。
- 未领取显示“立即领取”，请求中禁用按钮，防止重复点击。
- 初次查询已领取时首页不展示浮窗；本次展示后领取成功则保留浮窗，按钮显示灰色禁用的“今日已领取”，设置页同样禁用。
- 关闭按钮在悬浮或键盘聚焦浮窗时显示；关闭只影响本次页面展示。
- 点击信息图标打开官网 https://www.vectcut.com/checkin-rules，不再展示规则浮层。绿框、红框和尺寸标注为设计注释，不属于实际 UI。
- 窗口重新获得焦点不查询签到状态；同次启动复用已取得的结果。
- 查询接口未上线、请求失败或缺少必填字段时隐藏浮窗，不显示虚构的数量或领取状态。
- 总积分按钮继续打开充值页和刷新余额，不触发领取。
