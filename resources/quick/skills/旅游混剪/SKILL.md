# 旅游混剪网页技能

当用户想要“开发一个旅游混剪网页”“做一个旅游混剪 HTML 页面”“生成一个旅游空镜混剪演示页”“解释旅游混剪接口逻辑”时，触发这个技能。

这个技能既能直接产出可运行网页，也能围绕现有旅游混剪页面回答接口链路、任务状态、报错原因，并在需要时对现有实现做最小修改。

默认面向对象不是程序员，而是完全不会剪辑、只想做旅游混剪视频的普通商家或内容用户，因此页面交互应优先采用“上传区 + 填表单 + 一键生成”的方式，而不是暴露原始 JSON 请求体。

## 功能边界

### A. 直接生成网页

当用户要“开发一个旅游混剪的网页”“生成一个旅游混剪工具页”时：

- 直接创建或修改网页文件
- 默认最终交付为 `website/index.html`
- 默认内置可执行的接口调用逻辑，而不是静态示意
- 默认使用表单和素材表格收集信息，不直接让用户编辑原始请求体

### B. 回答逻辑 / 原理 / 微调现有实现

当用户是在问：

- 这个网页的逻辑是什么
- 为什么轮询一直没结束
- 这里是不是超时了
- 这个模板参数怎么传
- 帮我改一下默认模板
- 帮我补错误详情

此时本技能也必须触发，并具备：

- 阅读真实实现并解释请求链路
- 结合接口返回分析报错原因
- 对已有 HTML 做最小改动
- 说明关键字段、阶段含义和轮询策略

## 核心目标

根据用户需求，生成一个完整、可运行、可直接打开的网页，优先满足以下要求：

1. 页面可直接落地为 HTML 文件。
2. 页面结构完整，至少包含输入区、操作区、状态区、结果区。
3. 页面可以直接调用混剪模板接口。
4. 如需求不完整，优先做“默认可用版本”，避免停留在方案层。
5. 出错时必须能看到结构化错误详情，便于联调。

## 默认产出规则

若用户没有额外指定，默认按以下方式实现：

- 产出单文件 `website/index.html`
- 内联 `CSS` 与 `JavaScript`
- 中文界面
- 桌面优先、移动端可折叠的卡片式布局
- 默认提供一个可点击恢复的旅游混剪模板
- 页面文案必须面向普通商家，尽量不用技术术语
- 不直接暴露 JSON 编辑器，内部自动把表单转成接口参数
- 轮询超时时间默认 20 分钟
- 失败必须能看到 `phase`、`taskId`、`url`、`httpStatus`、`response`
- 如存在参考实现，优先吸收 `website/index.html`

## 接口参考（必须按此对齐）

当用户要求网页“能跑通接口链路”，生成的 HTML 应内置以下接口调用。所有请求均使用：

- Header：`Authorization: Bearer <token>`
- Header：`Content-Type: application/json`

### 1) 提交旅游混剪任务

- URL：`POST https://open.vectcut.com/cut_jianying/agent/submit_agent_task`
- 关键返回字段：`task_id`

### 2) 查询旅游混剪任务状态

- URL：`GET https://open.vectcut.com/cut_jianying/agent/task_status?task_id=<task_id>`
- 关键返回字段：
  - `status`
  - `message`
  - `output.draft_id`
  - `output.draft_url`
  - `output.video_url`

## 轮询与错误处理（必须实现）

网页必须包含如下行为：

- 每个异步任务轮询需有超时，默认 20 分钟
- `status=processing` 时继续轮询
- `status=success` 时结束轮询并展示结果
- `status=failed` 时展示结构化错误详情
- HTTP 失败、JSON 解析失败、参数校验失败、轮询超时都必须单独标记 `phase`
