# 餐饮门店混剪

这是一个餐饮门店短视频制作技能。默认只需要用户给出门店主题和门店素材视频，技能先按探店种草口播风格生成文案（约30秒），再按素材内容和时间轴生成一套竖屏餐饮门店混剪视频。

## 限制

- 默认输入必须有餐饮门店主题和门店素材视频。主题可以是门店名称、菜系类型、招牌菜品、消费场景等，例如"日料omakase探店"、"重庆老火锅新店开业"、"社区咖啡店日常"。
- 门店素材至少 1 条，优先使用视频；图片也可以混用。素材可以是本地图片或者视频，也可以是视频、图片链接；素材总个数不超过20，总时长不超过20分钟。为避免逐条理解产生过长上下文，视频素材原则上不超过20条；超过20条时直接停止并请用户先筛选素材。
- 用户没有给主题时，先问主题；没有给门店素材时，先问素材。缺任一项时不创建草稿、不生成配音。
- 最终成片时长约 30 秒，文案控制在 120～150 个汉字。

## 执行步骤

> **严格顺序执行规则**：每个步骤必须完全执行成功并确认结果后，才可以进入下一步。禁止跳步、禁止在异步任务未完成时提前执行后续步骤。特别是：
> - 第 4 步（生成音频）必须拿到音频 URL 后才能进入第 5 步。
> - 第 5 步（识别字幕）必须拿到完整字幕分段时间轴后才能进入第 6 步。
> - 第 8 步（字幕模板）必须等待任务状态变为 `success` 后，才能进入第 9 步。
> - 每一步遇到错误或超时时，必须先重试或诊断失败原因，不得在未解决的情况下继续后续步骤。

1. 检查限制。必须先确认有餐饮门店主题和门店素材；素材至少 1 条、不超过 20 条、总时长不超过 20 分钟。缺主题或缺素材时先询问；素材条数超过 20 时直接停止并说明原因。获取总时长的方式：先判断每条素材是本地文件还是网络链接；本地文件直接用本地路径，网络链接直接用 URL；然后调用 `scripts/calc_total_duration.py` 脚本计算总时长（该 Python 脚本同时支持本地文件路径和远程 URL，内部使用 ffprobe 逐条获取时长并汇总），总时长超过 20 分钟时停止并说明原因。这一步必须用脚本固定实现，不依赖人工估算，确保结果稳定可复现。调用方式：
   ```bash
   python3 scripts/calc_total_duration.py <file_or_url_1> <file_or_url_2> ...
   ```
2. 理解视频素材内容并并发保存结果。采用并发方式处理视频素材，一次并发数量不超过 15：先判断每条视频是不是本地文件；如果是本地文件，先并发上传成临时视频链接（一次最多 15 个并发上传），然后并发理解这些视频（一次最多 15 个并发理解任务）；每个视频理解成功并取得完整文字理解结果后，必须立即写入工作区的 `video_understanding/` 目录，每条视频单独保存为一个 UTF-8 Markdown 文件，文件名使用三位素材序号和经清理的原文件名，例如 `001-海边日落.md`，至少记录素材序号、原始文件名或 URL、临时上传 URL（如有）、理解任务 ID、完整理解结果。如果素材总数超过 15，分批处理，每批最多 15 个并发。不要把所有完整返回结果长期保留在对话上下文中；后续生成文案和分镜时按需读取结果文件，并优先使用各文件中的内容摘要和时间段信息。每次理解视频可能比较慢，大约需要 1~5 分钟；所有视频都必须取得文字理解结果并成功保存，任一视频没有理解结果或保存失败时停止。
3. 生成探店口播文案。用户没有给口播文案时，先根据主题和第 2 步得到的视频理解结果自动生成文案。最终成片约 30 秒，文案控制在 120～150 个汉字。生成文案时必须结合每条素材的视频理解结果中记录的时长信息，预先规划每段文案对应的画面素材及其可用时长；每条素材在文案中分配的画面时长不得小于 1.5 秒，时长不足 1.5 秒的素材不得作为独立画面使用（可与其他素材拼接后合并使用，但拼接后总时长仍须 ≥ 1.5 秒）。如果某条素材总时长本身就小于 1.5 秒，则不将其纳入文案的画面对应计划中。文案生成完成后，需同步输出一份简要的「文案-素材对应表」，列出每段文案对应的素材序号、素材可用时长和计划画面时长，确保所有计划画面时长均 ≥ 1.5 秒。文案风格提示词（严格按以下风格特征生成，不得引用任何示例中的具体店名或菜品名）：
   - **开头**：用一句有冲击力的感叹或反问开场，直接勾住食欲（如"这口下去谁顶得住啊"类型），语气热情、有感染力，一秒抓住注意力。
   - **门店定调**（1 句）：用一句话点出门店的核心记忆点——可以是氛围、定位、主厨背景或食材特色，传递"这家店不一般"的感觉；没有真实信息时跳过，不要硬编。
   - **菜品/亮点逐一展示**：按画面素材顺序，用短句逐一描述 2～4 个核心亮点（菜品、环境、制作工艺等），每句突出一个视觉或味觉冲击点，句式简洁有力，多用通感描写（如"滋滋冒油"、"一口爆汁"、"拉丝拉到天花板"），必须基于素材真实画面。
   - **价格/性价比锚点**（可选）：如果素材或主题中有人均消费信息，用一句话点出性价比，制造"值得冲"的感觉；没有精确数字时跳过，不要硬编。
   - **结尾互动**：用一句引导到店、收藏或评论的话收尾（如"地址放评论区了"、"赶紧@你的饭搭子"类型），制造行动转化。
   - **整体语气**：探店种草体，节奏快、信息密度高、每句都有画面感和食欲感，像美食博主面对面安利，让人看完就想冲。
   - 没有精确数字信息时不要硬编数字。文案默认 120 到 150 个汉字（匹配约 30 秒口播时长）。
4. 将口播文案生成音频，使用音色gv_989402eaac7b421ca713864f2da2aeb8，成功后必须取得口播音频 URL，没有音频 URL 时停止。
5. 识别字幕。识别第 4 步生成的口播音频字幕，固定使用 LLM 档位，成功后必须取得完整文本和分段字幕时间轴，没有字幕分段时停止。
6. 生成分镜计划。把第 2、5 步得到的视频理解结果和字幕时间轴交给模型生成 1 套分镜计划；先以字幕时间轴为主轴，再让视频内容向主轴靠拢，计划必须覆盖完整时间轴、只使用真实素材索引，且时间片段必须完全连续：首段 `start=0`，每段 `start` 必须等于上一段 `end`，最后一段 `end` 必须等于总时长，不能有空隙、负时长或重叠。每个分镜时长必须控制在 **1.5 秒到 3.5 秒之间**，超出 3.5 秒的分镜必须拆分为多个子分镜，不足 1.5 秒的分镜必须与相邻分镜合并。每个分镜还必须同时生成**原素材截取片段**（`source_start` 和 `source_end`），表示从该素材中截取的起止时间。注意：源片段时长（`source_end - source_start`）**不要求等于**目标时间轴上的分镜时长（`end - start`），因为字幕时间轴决定了分镜在目标轴上的位置，而源片段的选取是根据画面内容决定的，两者天然可能不一致。系统会根据 `starts/ends`（原始视频截取起止时间）和 `target_starts/target_ends`（目标轨道起止时间）的差值自动进行变速处理，无需手动计算速度。解析模型分镜后只允许做轻量边界校正：例如把最后一段补齐到总时长，或把毫秒级相邻边界对齐；不得因为很小的尾差丢弃语义匹配更好的计划。分镜计划生成完成后，必须将完整的分镜计划以 JSON 格式保存到工作空间文件 `storyboard.json` 中，每个分镜至少包含以下字段：`shot_index`、`start`、`end`、`source_clip`（素材序号）、`source_start`、`source_end`、`description`。后续第 9 步直接读取该文件执行，不再重新计算分镜。
7. 创建草稿。草稿固定竖屏，封面可选，成功后必须取得草稿 ID 和草稿 URL。
8. 添加字幕模版。从下面四个字幕模板 ID 中随机选一个，对第 4 步生成的口播音频使用字幕模板识别，并将识别结果添加到第 7 步创建的已有草稿中。注意：使用字幕模板的同时必须将口播音频也添加到草稿中（`addMedia=true`），确保配音音频和字幕一起写入草稿。可选模板 ID：asr_1f9c8d7e6a2b4c0d9e8f123456789abc, asr_6a4f2c9e8b1d4f7aa3c5e9d02b6f8c13, asr_9d550677d16a4c879a19bfeee1623a38, asr_e7c1a9d4b6f24c8e91a3d5b7f0c2e6a8。
9. 添加画面素材。读取第 6 步生成的 `storyboard.json` 文件，使用批量添加视频接口（`add_batch_video`）一次性将所有分镜的视频片段添加到草稿中。批量添加时，每个视频的参数从分镜计划中直接读取：`source_clip` 映射为对应的视频文件路径、`source_start` 和 `source_end` 作为源片段的起止时间（`starts`/`ends` 数组，表示原始视频截取开始/结束时间）。**注意：必须设置 `durations` 参数**，值为每个视频素材的**原始总时长**（通过 `get_media_duration` 预先获取，单位为秒），不是目标时间轴上的播放时长，否则 API 会报"视频时长无效: 0.0"错误。目标时间轴位置通过 `target_starts`/`target_ends` 数组指定（表示目标轨道的开始/结束时间）。系统会根据源片段时长和目标时长的差值自动进行变速处理，无需手动传递 `speed` 参数。**`target_starts` 和 `target_ends` 必须同时传递**（都是数组），只传其中一个会报"需要同时传入数组，或同时不传"错误。**⚠️ 必须设置 `volume=-60`（静音）**，避免原始视频声音干扰配音和背景音乐。批量添加和单条添加都需要传此参数。如果批量添加失败，则回退为逐条串行添加作为兜底方案。发生素材轨道冲突时先修正时间轴，只在明确轨道重叠错误时重试备用轨道。关于 `durations` 参数的详细说明和示例见下方"常见问题 → 1. `add_batch_video` 批量添加视频失败"。
10. 添加背景音乐。背景音乐从 `references/bgm.md` 里随机选一个，再写入草稿。背景音乐的时长必须与第 4 步生成的配音音频时长一致。添加音频时，截断通过 `start` 和 `end` 参数控制（表示从原始素材中截取的起止时间），`duration` 是原始素材的总时长（不可用于截断）：如果背景音乐时长超过配音时长，设置 `start=0`、`end=配音时长` 即可截断多余尾部；如果背景音乐时长不足配音时长，需要多次调用添加音频接口循环拼接，每次通过 `start` 和 `end` 指定从原始素材中截取的片段范围，直到覆盖完整配音时长（最后一段的 `end` 截断到精确对齐）。背景音乐轨道为 `bgm_audio`，音量设置为 `3`。
11. 最终校验。检查草稿脚本内容；检查是否有空隙、是否连续、字幕、配音、背景音乐是否都加上了。
12. 下载草稿。调用下载接口将第 7 步创建的草稿下载到本地，必须传入草稿 ID 和草稿名称。
13. 返回结果。展示思考切片的关键环节，不展示请求回包的具体细节。最终输出必须包含草稿下载链接。并且直接触发下载这个草稿。

## 常见问题

### 1. `add_batch_video` 批量添加视频失败

**现象**：调用 `add_batch_video` 时返回错误或片段未正确添加到草稿中。

**原因**：批量添加视频时，每个片段必须同时设置 `durations` 参数（表示该视频素材的**原始总时长**），否则接口无法正确识别素材，导致添加失败。

**解决方法**：在 `add_batch_video` 调用中，为每个片段显式传入 `durations` 数组，值等于该视频素材的**原始总时长**（通过 `get_media_duration` 获取，单位为秒），而不是时间线上的播放时长。示例：

```json
{
  "video_urls": ["素材路径1", "素材路径2"],
  "starts": [0, 5.0],
  "ends": [3.0, 8.0],
  "durations": [15.2, 12.8],
  "target_starts": [0, 3.0],
  "target_ends": [3.0, 6.0]
}
```

其中 `durations[i]` 是第 i 个视频素材的原始总时长（通过 `get_media_duration` 预先获取），`starts[i]` 和 `ends[i]` 定义从原始素材中截取的片段范围，`target_starts[i]` 和 `target_ends[i]` 定义在时间线上的放置位置。
