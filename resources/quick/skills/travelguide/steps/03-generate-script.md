# 步骤 3：生成攻略口播文案

> 用户没有给口播文案时，先根据主题和第 2 步得到的视频理解结果自动生成文案。文案生成必须严格遵循"先规划画面时长、再按字数写文案"的流程。

## 输入定义（OpenAPI 3.1）

```yaml
requestBody:
  required: true
  content:
    application/json:
      schema:
        type: object
        required: [travel_theme, understanding_dir]
        properties:
          travel_theme:
            type: string
            description: 旅行主题。
          understanding_dir:
            type: string
            description: 步骤 2 的理解结果目录。
          oral_script:
            type: string
            description: 可选，用户已有的口播文案。提供时跳过自动生成，直接进入 3d 校验。
```

## 操作规则

### 3a. 提取可用画面片段清单

从第 2 步的视频理解结果中，按 0.3 秒粒度提取所有可用画面片段，汇总成一份"可用画面清单"，每条记录包含：素材序号、时间段（如 0~2.5秒）、画面内容摘要。将语义连续的多个 0.3 秒片段合并为一个"画面段"（如 0~2.5秒的连续画面合并为一个段），每个画面段的时长必须 ≥ 1.5 秒。

### 3b. 规划画面段与口播时长的对应关系

中文旅行攻略口播的语速约为**每秒 4～5 个字**（含标点停顿）。根据总目标时长约 45～60 秒，从可用画面清单中选出 15～20 个画面段，为每个画面段分配目标口播时长（1.5～3.5 秒），并计算该时长内最多能说多少字（画面段时长 × 4.5 = 最大字数）。所有画面段的目标时长之和应约等于 45～60 秒。

### 3c. 逐段撰写文案

按规划的画面段顺序，为每个画面段撰写对应口播文案。**每句文案的字数必须严格不超过该画面段的最大字数限制**（即 画面段时长 × 4.5）。例如：某画面段分配 2 秒，则对应文案不能超过 9 个字；分配 3 秒，则不能超过 13 个字。绝不允许出现一句文案跨越多个画面段、或一个画面段内塞入过多文字的情况。

### 3d. 输出「文案-画面时长对照表」并校验

文案写完后，必须输出一份对照表，逐行验证每句文案的字数是否在其画面段的字数限制内。如果任何一句超出限制，必须立即修改文案（缩短句子或增加该画面段的时长），直到全部通过校验。

| 画面段 | 素材 | 时长 | 最大字数 | 文案内容 | 实际字数 | 是否通过 |
|--------|------|------|----------|----------|----------|----------|
| 段1 | 素材1 0~2.5s | 2.5s | 8字 | "第一次来先看这条" | 8字 | ✅ |
| 段2 | 素材2 1.0~4.0s | 3.0s | 10字 | "两天一晚也能玩得很满" | 10字 | ✅ |

### 文案风格规则

严格按以下风格特征生成，不得引用任何示例中的具体地名、景点或人物：

- **开头**：用一个设问句制造悬念，紧跟一句肯定回答，语气轻快有感染力，一秒抓住注意力。
- **引导收藏**：紧接着用一句话引导收藏，并点出天数、预算或玩法亮点；没有精确数字时跳过具体数字，不要硬编。
- **人物引入**（可选）：用一句话简要介绍出行人物和来源，增加真实感和代入感；没有真实人物信息时跳过，不要硬编。
- **行程定调**：用一句话概括行程安排特点（如不赶不累、适合周末、主打拍照出片、吃逛都顺路等），传递轻松感和可执行性。
- **分站点/玩法展示**：按画面素材顺序，用短句逐一描述 2～4 个核心亮点（景点、路线、玩法、住宿氛围、夜景、美食打卡等），每句突出一个真实可见的视觉记忆点，必须基于素材真实画面。
- **预算/性价比锚点**（可选）：如果素材或主题中有明确预算、人均或交通信息，用一句话点出性价比；没有精确数字时跳过，不要硬编。
- **结尾互动**：用一句引导收藏、评论或私信的话收尾，制造行动转化。
- **整体语气**：口播攻略体，节奏快、信息密度高、每句都有画面感，像在跟朋友面对面安利一条值得照着走的路线。
- 没有精确数字信息时不要硬编数字。文案默认 180 到 280 个汉字（匹配约 45～60 秒口播时长）。

## 输出定义（OpenAPI 3.1）

```yaml
responses:
  "200":
    description: 口播文案生成完成，对照表校验通过。
    content:
      application/json:
        schema:
          type: object
          required: [script, word_count, segment_table]
          properties:
            script:
              type: string
              description: 完整口播文案。
            word_count:
              type: integer
              description: 文案总字数（180~280）。
            segment_table:
              type: array
              description: 文案-画面时长对照表。
              items:
                type: object
                properties:
                  segment_index:
                    type: integer
                    description: 画面段序号。
                  source_clip:
                    type: integer
                    description: 素材序号。
                  source_start:
                    type: number
                    description: 素材截取起始时间（秒）。
                  source_end:
                    type: number
                    description: 素材截取结束时间（秒）。
                  duration:
                    type: number
                    description: 画面段时长（秒）。
                  max_words:
                    type: integer
                    description: 最大字数限制。
                  script_text:
                    type: string
                    description: 对应口播文案。
                  actual_words:
                    type: integer
                    description: 实际字数。
  "500":
    description: 文案生成失败或校验未通过。
```
