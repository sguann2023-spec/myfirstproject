## Context
目前某个视觉分析批次失败会让整个工具报错，导致 Agent 无法把它作为“识别不完整”的业务结果处理。改为正常返回工具结果，但明确说明识别范围与缺失内容，由 Agent 决定是否重试、降低采样率或采用其他分析策略；不把未识别伪装成成功识别。

## 实施方案
1. **视频理解返回结构**（`src/main/mcpServers/video-understand.ts`）
   - 增加独立业务字段：`recognition_status`（`complete` / `partial` / `unrecognized`）、`recognition_complete`、说明及失败/未尝试的批次和时间范围。
   - 视觉模型请求在现有最多 3 次尝试后仍失败，转为正常业务结果，不设置 MCP `isError`、顶层 `error` 或 `success: false`。
   - 保留已经成功的批次；停止该视频后续视觉分析，不额外自动重跑。其他正在处理的视频仍保留各自结果。
   - 返回明确建议：内容未完全识别，可重试或采用其他策略，由 Agent 根据任务自行决定，不自动发起新增付费任务。
   - 参数错误、登录过期、主动取消和文件保存等非理解错误保留原错误语义；现有重试次数不变。
2. **保留结果和费用**
   - 复用现有 Markdown、索引及 JSON artifact 保存函数，不完整结果同样输出文件，标明缺失范围；不丢掉已有理解内容。
   - 保留服务端已返回的 billing；已知收费的空回答也不能丢失账单。未知费用不当成已确认的零费用，识别完整性与账单完整性分别表达。
3. **直连及界面适配**
   - 修改 `src/shared/videoUnderstand.js` 的 `parseVideoUnderstandResult`，接受上述正常业务结果；摘要明确“未完全识别”，不再宣称完整内容已保存。
   - 修改 `videoUnderstandeTool.ts` 和 `VideoUnderstandeToolRenderer.tsx`，在概览中展示不完整提示及原因，同时保留积分和文件入口。
   - 外部异步调用通过正常任务结果携带识别状态，避免将未完全识别再次转为工具错误。

## 验证
补充并运行现有视频理解、直连、shared parser 和 renderer helper 单测，覆盖：第一批即失败、成功一批后失败、多视频部分失败、空回答含费用、Agent 可见的未完成提示，以及参数错误/取消/登录过期仍保持原行为。测试使用 mock，不发起实际收费请求。

不修改积分预估公式，不调整模型或采样率，不处理无关工作区改动。
